# v2 additive API (engine)

Existing `CompanionProvider.send`, `CompanionRequest`, tools, `CompanionSession`, and primitive drawings remain source-compatible.

Public v2 entry points (implemented in corresponding Swift files):
- `CompanionProvider.stream(_ request: StreamRequest) -> AsyncThrowingStream<ProviderStreamEvent, Error>`; default implementation fails explicitly for old providers. `cancelStream()` / `shutdown()` default no-op. Built-in providers implement streaming.
- `StreamRequest(model:input:purpose:patterns:)`, `StreamPurpose.answer / gate / repair`, stable `system`, `prefix`, `context`, `changed`, `images`, `wirePreview`; `NoteImage` carries id, MIME, bytes. `RequestInput` gains `images` with an empty default (also accepted by its initializer); `attachments` includes those plus any page PNG. Both v1 and v2 built-in routes send the actual attachments, while previews contain only summaries.
- `CompanionEngine(provider:models:inspector:stateFolder:budget:)` actor, one per note. `configure(mode:unpinnedNotes:)`, `activity(at:)`, `idleActivity(at:)`, `events(for:at:confirmedBudget:)`, `cancel()`, `shutdown()`, `meter()`, `setLimits(tokens:requests:)`, async `setModels(_:)` (cancels the prior pass), `lastRequest`. `EngineEvent.ask(RequestInput) / reply(RequestInput) / pause(RequestInput)` inputs. Async output (`EngineOutput`): `.firstToken`, `.textPreview(StreamTextPreview?)`, `.item(StreamItem)`, `.pictureStep(id:svg:step:)` provisional, `.pictureReplace(id:svg:findings:)` (nil = remove preview; display any `fallback` finding beside existing prose, without adding another read-along margin), `.usage`, `.gate`, `.finished`, `.cancelled`, `.failed`. `StreamTextPreview` has `quote: String?`, `threadID: String?`, `kind`, `text`; nil clears the provisional margin/reply. It is emitted only after a complete valid routing prefix and never stored. Hosts discard provisional text/steps on cancellation. Complete `.item`s are storage candidates, **staged until `.finished`**; `.failed` may commit a complete valid prefix, `.cancelled` discards all staged additions from that pass. This is required for byte-for-byte note preservation when typing cancels. Engine never writes note content.
- `StreamItem` plain values: `.quiet`, `.margin(quote:kind:text:)`, `.picture(id:quote:title:svg:)`, `.reply(threadID:text:)`, `.sources([Source])`. Quotes must resolve in request; reply IDs must exist. `ItemStreamParser` incremental strict framing. Call `finish(emit:)` after a successful provider terminal event: EOF is accepted as the last record delimiter (models omit a trailing LF). Plain `finish()` only validates already LF-delimited records.
- `PictureInspector: Sendable`: `filter(svg:) throws -> String`, `displayList(svg:) throws -> PictureDisplayList`. Host implements with core; `PictureDisplayList`/`PictureStep`/`PictureDrawItem` are core-independent plain Codable values. Draw items include optional `bounds`, linear `transform`, `font`, `baseline`, `strokeWidth`, `closed` with default nil, preserving source compatibility. Copy core bounds/transforms for rotated text; arrowheads may be inferred after marker flattening. `PictureCheck.inspect(_:commentary:) -> [PictureFinding]`. See README for thresholds.
- `PatternBook.all`, `.closest(to:limit:additional:)`; twelve bundled SVG patterns. `.addPinned(svg:description:tags:at:inspector:)` and `.loadPinned(at:)` store only checked user-selected pictures in host app state; 100 entries/3 MiB, deduplicated. Engine includes those if stateFolder is supplied. `ModelSettings.defaults(from:)` selects only IDs in the provider catalog. `ProviderModel` gains optional `inputCost`/`outputCost` (default nil); Codex populates them. Gate uses lowest listed positive combined cost, or small-family ranking; answer uses strongest-family/latest-version ranking. On this catalog: GPT-6 Luna / GPT-6.1 Sol. Gate and answer are separately user-configurable.
- `LocalDecisionLog` JSONL in host-supplied app state, `recordFeedback(action:passage:itemID:)`; actions dismiss/pin/addToNote. Never stores credentials or image bytes.
- `CodexCLIProvider.stream` / `streamPreview` provide the existing native Web/absent-pi fallback, consuming agent-message JSON records (item-level, not guaranteed token streaming). `CodexProvider.stream` selects it for Web; all regular signed-in passes use persistent pi.
- Legacy `wirePreview` methods now substitute image summaries, and `CompanionSession.lastRequest.pagePNG` is nil to avoid persisting bytes in last-request logs; the user/wire strings include image size/hash.
- `RequestInput` decoding is backward-compatible when the new images field is absent.
- `CodexProvider(executable:trace:)` accepts an optional credential-free RPC trace callback. It omits prompts, images, message snapshots and errors; intended for marked smoke exchanges only.
- `JudgmentCase`, `JudgmentRunner`, `JudgmentResult` expose injectable scoring; the CLI supports offline recordings/replay and an external core inspector.
- `swift run SyncrJudge` defaults to offline recorded judgment; `--route codex --live-manual` opts into signed-in baseline. See README.

Streaming pictures are not enabled for storage without a production inspector. A rejected/check-failing picture falls back to words; the host need not link the core into this package.

## Speed round (companion-speed, 2026-11-22)
- `CompanionEngine(..., trace: TraceSink? = TraceSink.fromEnvironment())`: opt-in stage trace. Off unless a sink is given or `SYNCR_COMPANION_TRACE=<file>` is set; then one JSON line per pass: stage times in milliseconds since `ask` (`started`, `answer.request_built`, `answer.provider_start`, `answer.child_ready`, `answer.prompt_sent`, `answer.first_record`, `answer.first_text`, `answer.first_byte`, `text_shown`, `picture_step_parsed`, `picture_step_shown`, `done`, and the same under `gate.` / `repair.`) and a few short facts (`answer.cold` 1 when the provider process had to be started, `answer.promptBytes`, `step.filter_ms`, `step.check_ms`, `outcome`). Fixed names, numbers only: never prompt, note or answer text.
- `StreamRequest.trace` (set by the engine) lets a provider mark its own stages.
