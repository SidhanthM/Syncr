# Offline v1 fixtures and deterministic acceptance tests

`manifest.json` has `fixture_version=1`; each case supplies `name`, `input_path`, `expected_path`. Expected definitions are authored static goldens, not regenerated from current Rust results during tests. Canonical IDs and enum labels follow the contract. u64 fixture values (local sequences) are decimal strings; samples are base64 (the test loader expands them into typed byte vectors). JSON tagged commands here are typed test data, **not** a new dispatch/FFI API.

## Legacy file fixture

`fixtures/legacy-v1/note-v1.syncr` and `library-v1.sqlite3` are real files written by the pre-page-format core (note schema v1, library schema v1, SYNO creation tag 0, sequence 6), copied from the earlier legacy probe. `tests/formats_notebooks.rs` copies them into a temporary root (never opening the fixtures in place) and checks Sheet16x10/Inbox reads, ULID fallback timestamps, legacy creation retry identity, the v1 → v3 upgrade (with backup) and new commits.

## Failure/lifecycle fixture tests

The following deterministic programmatic fixtures exercise real public APIs/SQLite, not mock durable outcomes:

- `failure_tests::process_exit_before_after_commit_and_publication`: child processes exit with code 91 at five test-only boundaries: creation before commit, creation after commit but before publication, after no-overwrite rename publication/directory sync, command before commit, command after commit/before reply. Parent reopens, reconciles temp files, checks exact operation presence and sample bytes, recovers lost results and verifies retries do not duplicate. Fault code is compiled only under `cfg(test)`; production has no environment-controlled failure switches.
- `library::tests::actual_sqlite_full_rolls_back_projection_samples_log_history_and_events`: caps the **actual note connection's** SQLite `max_page_count`, submits valid measured data, obtains real `SQLITE_FULL` → retryable `StorageFull`, checks unchanged snapshot/cursor/history, absent log/sample record, reopens and successfully retries the same immutable command.
- `library::tests::interrupted_index_update_is_recovered_from_published_metadata`: a failing SQLite cache-insert trigger remains active while creation, lookup, retry and listing recover the authoritative published note.
- `library::tests::stale_inverse_heads_abort_the_entire_batch`: both Undo and Redo two-target inverses with a simulated foreign head on the second target; the snapshot exposes the current foreign head and the test submits its exact dependency list. Durable dependency presence is supplied so `StaleBase` is not masked by `MissingDependency`. No first-target mutation, sequence or stack change is installed. A current-head read model does not bypass expected-head validation. This deliberately simulates a future foreign head in test-only internals; no foreign-author production API is added.
- `library::tests::close_checkpoint_failure_keeps_handle_open_and_export_failure_is_not_success`: a real SQLite read transaction pins the WAL and makes close checkpoint fail; the handle stays usable and later closes successfully. Invalid export-parent failure cannot overwrite a sentinel or claim success.
- `tests/offline.rs`: independent-mark heads despite newer global sequence; explicit restore and preserved stacking; exact transform/style inverses; redo through multiple same-mark undo steps; metadata/structure preserving redo; exact reorder permutation; direct sheet-creation dependency; immutable payload/envelope/sample/effect storage; absent/out-of-order dependency rejection; eight concurrent same-ID submissions with exactly one new commit; aggregate 16 MiB and 64 KiB metadata rejection with unchanged state.
- `tests/offline.rs`: snapshot-before-commit invalidation; all 256 ring entries and expiry boundary, pagination, future/wrong/reopened streams, invalid limits, no-change cursor; shared live writer; successful/idempotent close and `Closed` on all other calls.
- `tests/offline.rs`: live-WAL SQLite backup, version/state/integrity validation, no overwrite, arbitrary backup filename discovery/reopen, immutable samples/authorship and different-installation history isolation; newer note version rejection without changing file bytes.
- `tests/boundary.rs`, `src/validation.rs`, `src/error.rs`: process writer exclusion, note retaining root lock, installation persistence, WAL/FULL configuration, newer library version with unchanged bytes, canonical ULID and affine rejection, target/count/dependency abuse, confirmed-base rejection, maximum valid sample size, and typed/redacted storage errors.
- `tests/dependencies.rs`: exact creators for all four sheets after add/reorder/rename/full library restart, negative missing/latest-structure/other-sheet witnesses, successful adds from exposed creators and unchanged schema version. Exact history dependency lists with 1,152 unrelated marks and distinct unrelated heads, repeated/mixed heads, tombstones, both lists across restart, structural/metadata preservation, stale target/head dependency failures, immutable retries and redo-branch clearing.
- `dependency_tests::history_snapshot_has_exact_sorted_1024_current_heads_without_truncation`: reducer-only boundary fixture, 1024 distinct affected current heads after per-mark edits/undos, sorted without truncation, then deduplicated to one tombstone head. This is read-model boundary coverage, not a claim that a 1024-stroke Add passes the independent 64 KiB metadata limit. Missing/foreign-author history yields empty lists.
- `examples/kotlin/Consumer.kt`: actual generated Kotlin → Rust host execution for create/add/snapshot/erase/undo/redo/export/closeNote/reopen and library restart, plus four-sheet add/reorder/rename/full restart/draw with exact provenance, structure-head rejection, history-list consumption, redo after restart and immutable retry. Also native typed errors and exact diagnostics, optional samples and unsigned converters.

## Scope of evidence

Dependency-amendment suite: **35 Rust tests passed**, plus child-process probes and both staged/published real host Kotlin flows. Pinned Android arm64 native rebuild and all 89 generated external-symbol checks passed. A local old-writer/new-reader compatibility probe also reopened a note created by the pre-amendment published host library and exercised its persisted samples/history with no schema migration; evidence is retained in `generated/legacy-probe/`. These checks do not establish Android device loading, UI behavior, phone installation, arbitrary mid-commit crashes, power-cut/filesystem guarantees, security audit or renderer/latency acceptance. Publication is tested via same-directory no-overwrite renames (`renameat2(RENAME_NOREPLACE)` / `renamex_np(RENAME_EXCL)`, never hard links) and successful file/directory fsync on the host; see the core README for filesystem assumptions and the frontend dependency-field handoff.
